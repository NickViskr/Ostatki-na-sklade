# Стенд для проверки Code.gs

`Code.gs` — бэкенд на Google Apps Script. Обычными тестами он не проверяется: его нельзя запустить ни на компьютере, ни в браузере, потому что он опирается на службы Google (`SpreadsheetApp`, `Utilities`, `Session`, `Logger`), которых вне Google не существует.

Раньше единственной доступной проверкой была синтаксическая — «файл хотя бы разбирается». Про то, правильно ли он **считает**, она не говорит ничего. Для боевого учёта этого мало: ошибка в расчёте — это реальные деньги.

Стенд закрывает пробел. Он подменяет службы Google заглушками, подставляет фальшивую таблицу, которая честно хранит записанное, и выполняет **настоящий код из `Code.gs`** — не копию и не пересказ.

## Как запустить

```bash
npm run test:gas
```

Ожидаемый ответ — строка вида `=== ИТОГО: 56 проверок, провалено: 0 ===`. Если провалено не ноль, ниже будут перечислены упавшие проверки с фактическими числами.

## Что проверяется сейчас

Три функции, 56 проверок.

### `updateOzonStockHistory` — накопление истории наличия остатков Ozon (пункт 42 плана, этап E), 27 проверок по 8 сценариям:

1. первый за сутки опрос создаёт строки недели;
2. повторный опрос в тот же день ничего не меняет — автоопрос ходит дважды в сутки, и задвоение счётчиков сделало бы весь лист бесполезным;
3. на следующий день счётчики растут на единицу;
4. даты, вернувшиеся из таблицы объектами `Date`, а не строками, обрабатываются верно;
5. новая неделя не трогает прошлую;
6. срок хранения читается из настройки, а не из зашитого числа;
7. сочетание, появившееся среди недели, получает свой счётчик наблюдений, а не чужой;
8. несколько складов одного кластера сворачиваются в одну строку.

### `updateSkuNamesFromOzonStocks` — сохранение названия товара Ozon в лист SKU, 15 проверок по 9 сценариям:

1. колонка «Название Ozon» создаётся сама, если её ещё нет;
2. распроданный товар не теряет сохранённое название — ради этого всё и делалось;
3. изменившееся в Ozon название обновляется;
4. когда менять нечего, запись в лист не выполняется ни разу (проверяется счётчиком вызовов `setValues`, а не сравнением содержимого);
5. связывание по ШК Ozon, когда артикул в листе SKU не совпадает с артикулом Ozon;
6. ШК Ozon, пришедший числом и лежащий в таблице числом, всё равно связывается;
7. ШК Ozon, равный `0` (так хранится «баркода нет»), ничего не связывает;
8. пустое название не затирает сохранённое;
9. из нескольких складов берётся первое непустое название, лист переписывается один раз.

### `commitTransaction` — проведение Прихода/Расхода (пункт 40, этап B: «долг себестоимости» при списании), 14 проверок по 5 сценариям:

1. списание («Списание - Брак» / «Списание - Утеря»), опустошающее остаток артикула до нуля: количество обнуляется, капитализация НЕ обнуляется — это регресс-гвардия на дефект, из-за которого стоимость брака молча уничтожалась;
2. такое же списание, но с положительным остатком после: капитализация не трогается, средняя пересчитывается как капитализация/остаток;
3. обычный Расход (не списание) по-прежнему уменьшает капитализацию на себестоимость отгрузки — доказывает, что фикс не задел нормальное потребление остатка;
4. Приход на артикул с «долгом себестоимости» при нулевом остатке: капитализация становится долг+стоимость партии, средняя — от этой суммы; это и есть поведение, ради которого сделан фикс — долг поглощается ближайшим приходом;
5. то же списание до нуля, но для компонента виртуального комплекта.

Стенду для этого пришлось обзавестись фальшивыми листами «Остатки», «Транзакции» и «Комплекты» (реестр `sheetRegistry` в `harness.cjs`) и заглушками `Utilities.getUuid`/`SpreadsheetApp.flush` — раньше хватало одного листа SKU.

## Почему это стоило написать

Проверка №4 появилась после реального дефекта. Google Sheets превращает записанную строку `2026-08-17` в дату, и при следующем чтении возвращает объект `Date`. Код сравнивал его со строкой, сравнение никогда не срабатывало, и счётчики росли бы **по два раза в сутки** — лист копил бы неверные данные месяцами, никак этого не показывая.

Дефект не поймал бы ни синтаксический разбор, ни проверка типов, ни просмотр глазами: лекарство от него уже лежало в том же файле, в функции `normWeek`, в двадцати строках от места правки.

## Как добавить проверку новой функции

`harness.cjs` — окружение: заглушки служб Google, подменяемая «текущая дата», фальшивый лист. `run-tests.cjs` — сами проверки.

Порядок такой: в `harness.cjs` дописать нужную функцию в список выдаваемых наружу, в `run-tests.cjs` добавить сценарий. Каждая проверка обязана печатать фактическое значение рядом с ожидаемым — иначе по выводу невозможно понять, что именно разошлось.

Полезный приём: временно сломать проверяемый код и убедиться, что тест покраснел. Тест, который проходит всегда, не проверяет ничего.
